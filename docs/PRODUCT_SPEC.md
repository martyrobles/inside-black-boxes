# Blackletter Lab — Refined Product Vision and Feature Instructions

## Product Concept

Blackletter Lab is a private, AI-assisted creative intelligence library.

It allows the user to capture almost anything:

- Written notes
- Voice notes
- Photographs
- Screenshots
- Graffiti
- Signs
- Artwork
- Videos
- Audio recordings
- Articles
- Cases
- Judicial opinions
- PDFs
- Web pages
- Quotations
- Conversations
- Observations
- Product ideas
- Story ideas
- Legal theories
- Research
- Places
- People
- Objects
- Scenes
- Dreams
- Questions

The application does more than store material. It helps the user understand why each item matters, discover relationships among seemingly unrelated materials, and transform those materials into articles, projects, products, stories, images, presentations, screenplays, and other creative outputs.

The core workflow is:

**Capture → Describe → Understand → Connect → Develop → Create**

---

# 1. Product Promise

Blackletter Lab should allow the user to say:

> “I do not yet know what this is for, but it interests me. Save it, understand it, and help me discover what it could become.”

The user should not need to decide in advance whether something belongs to an article, screenplay, legal project, business idea, social post, or research project.

The application should preserve ambiguity until useful connections emerge.

---

# 2. Guiding Principles

## Capture Without Friction

The user should be able to save something in seconds.

The application should accept:

- Typed text
- Dictated text
- Recorded voice notes
- Photos taken within the app
- Existing photos
- Videos
- Audio files
- Documents
- PDFs
- Links
- Screenshots
- Pasted text
- Shared content from other applications

Uploading should require minimal mandatory information.

## Every Capture Has Context

For every item, the application should ask:

- What is this?
- Why did it interest you?
- What were you thinking when you saved it?

The user may answer by typing or speaking.

The required description should be brief. A one-sentence explanation is enough.

The system may also generate its own description, but it must preserve the user’s original explanation separately.

## Preserve the Original

The application must never replace or obscure the original material.

It should clearly distinguish:

- Original uploaded material
- User description
- User analysis
- Extracted text
- AI-generated description
- AI-generated interpretation
- AI-generated ideas
- Final user-approved work

## Connections Matter More Than Folders

Traditional folders force the user to decide where something belongs.

Blackletter Lab should allow one item to relate to many ideas and projects.

A photograph of graffiti might relate to:

- A legal article
- A short film
- A visual essay
- A branding concept
- An immigration story
- An urban history project

The application should emphasize relationships, themes, and possible uses rather than rigid filing.

# 5. Search and Retrieval

The system should support both ordinary search and conceptual search.

## Basic Search

Search by:

- Title
- Description
- Full text
- Transcript
- Case name
- Citation
- Author
- Source
- Date
- Tags
- Location
- People
- Project
- Content type

## Semantic Search

The user should be able to search using natural language, such as:

- Show me everything I saved about institutional power.
- Find images that could inspire a dystopian short film.
- What have I collected concerning AI delegation?
- Show me material related to loneliness in cities.
- Find cases and articles that could support my governance theory.
- What have I captured that might work as a Law360 article?
- Show me visual material connected to immigration.
- Find things I saved but never developed.

## Visual Search

The application should also support:

- Find visually similar images
- Search for text visible within photographs
- Search by objects shown in images
- Search by setting, mood, or visual style
- Find videos containing a particular object, phrase, or scene

## Search Results Should Explain Themselves

When an item appears in conceptual search, the application should explain:

- Why it matched
- Which text, image feature, or concept was relevant
- How confident the system is
- Which other items it connects to

- Professional but accessible tone

# 9. Recommended Additional Features

## A. Daily Reappearance

The system should periodically resurface older material.

Examples:

- You saved this one year ago today.
- This older photograph relates to your new AI governance idea.
- You have not revisited this promising concept in six months.
- Three recent uploads connect to this abandoned article idea.

This creates serendipity and prevents valuable material from disappearing.

## B. Creative Collision

The user selects two unrelated items, or the system chooses them, and asks:

> What new idea emerges when these are combined?

Examples:

- A Supreme Court case plus a piece of graffiti
- A legal doctrine plus a photograph
- A personal observation plus a technology article
- A historical case plus a science-fiction concept

The system should produce serious, plausible, and surprising combinations.

## C. Collections

Allow the user to create flexible collections such as:

- Possible Law360 articles
- Short-film imagery
- Legal AI governance
- Things seen in Chicago
- Immigration narratives
- Visual motifs
- Quotes worth using
- Future products
- Strange but promising ideas

An Artifact may belong to multiple collections.

## D. Idea Lineage

Every finished output should show its ancestry:

- Which Artifact inspired it
- Which Ideas contributed
- Which sources were used
- Which AI suggestions were accepted
- How the concept changed

This protects provenance and helps the user understand the development of their own thinking.

## E. Research Gaps

For any idea, the application should identify:

- Missing authorities
- Unsupported claims
- Competing views
- Questions requiring research
- Facts needing verification
- Legal developments that may affect the idea
- Sources that should be located

## F. Contrarian Mode

The user should be able to ask the system to:

- Challenge the premise
- Find weaknesses
- Identify clichés
- Explain why the idea may not be original
- Offer the strongest opposing argument
- Identify ethical risks
- Suggest a more surprising angle

## G. Audience Lens

Transform the same idea for different audiences:

- Practicing lawyers
- Law firm leadership
- Technologists
- Regulators
- General public
- Academics
- Students
- Investors
- Filmmakers
- Social-media audiences

## H. Perspective Shift

Reinterpret material through different lenses:

- Legal
- Technological
- Historical
- Philosophical
- Psychological
- Cinematic
- Political
- Commercial
- Ethical
- Personal

## I. Voice Profile

The application should learn the user’s preferred writing characteristics without impersonating them automatically.

The user may define preferences such as:

- Analytical
- Direct
- Witty
- Skeptical
- Professionally provocative
- Accessible
- Avoids clichés
- Avoids excessive headings
- Avoids corporate jargon
- Prefers strong thesis statements

The system should allow different voice profiles for:

- Legal writing
- Social media
- Screenwriting
- Internal professional writing
- Personal essays

## J. Incubation Queue

Not every idea should immediately become a project.

Allow Ideas to be placed into an incubation state, with fields such as:

- Why this may be promising
- What is missing
- Trigger for revisiting
- Related developments to watch
- Potential format
- Earliest next action

## K. Opportunity Detection

The system may periodically identify:

- Timely article opportunities
- Themes appearing repeatedly
- Ideas with unusually rich supporting material
- Concepts that could become products
- Images that could support visual storytelling
- Old ideas made newly relevant by recent captures
- Several weak ideas that become strong when combined

## L. Project Workspace

Once an idea becomes a Project, provide:

- Goal
- Audience
- Thesis or premise
- Source materials
- Outline
- Tasks
- Drafts
- Open questions
- Research gaps
- Version history
- Export options
- Related outputs

One Project should support multiple derivative outputs.

For example, a single project could produce:

- A Law360 article
- A LinkedIn post
- An X thread
- A podcast episode
- A presentation
- A visual image
- A later law review article

# 11. Important Product Distinctions

## Artifact

Something the user captured.

## Idea

An interpretation, proposition, concept, or possibility derived from one or more Artifacts.

## Project

A sustained effort to develop an Idea into something real. In the UI, active Projects appear under **Projects Underway** (for example, Inside Black Boxes).

## Output

A specific deliverable created from a Project or Idea.

## Collection

A flexible grouping of related items.

## Connection

An explicit relationship between two items.

This distinction will prevent the application from becoming an unstructured pile of notes.

# 14. AI Behavior Rules

The AI should:

- Preserve the user’s original material
- Explain the basis for its suggestions
- Cite internal source material
- Distinguish fact from inference
- State uncertainty
- Avoid inventing legal authorities
- Ask before permanently changing classifications
- Avoid silently overwriting user work
- Generate alternatives rather than a single supposedly correct answer
- Allow the user to accept, reject, edit, or save suggestions
- Maintain a history of accepted AI contributions

The AI should not:

- Treat every upload as requiring an immediate project
- Force all material into legal categories
- Automatically publish anything
- Present unverified legal research as reliable
- Hide the source of generated claims
- Replace user descriptions with AI summaries
- Make permanent connections without user approval

# 15. Central Product Differentiator

Blackletter Lab is not merely a place to save information.

Its distinctive value is the ability to answer:

- Why did I save this?
- What does it connect to?
- What patterns are emerging?
- What might this become?
- What have I overlooked?
- Which of my ideas are worth developing?
- How can one idea become several different outputs?
- How did the finished work emerge from the original material?

The system should function as a searchable external memory, an intellectual laboratory, and a creative collaborator.

# 16. Open Decisions and Proposed Refinements

This section refines the vision above for buildability. It does not replace Sections 1–15; it prioritizes and clarifies them for MVP.

## 16.1 Primary Persona (MVP)

**Decision:** Treat the primary MVP user as a solo practitioner / legal writer who also pursues creative side projects (essays, film concepts, product ideas).

Secondary audiences (filmmakers, general idea people, academics) remain valid, but capture flows, default output templates, and voice profiles should optimize for the primary persona first.

## 16.2 Capture Menu Reduction (MVP)

Ship four capture entry points in the first MVP (voice deferred):

1. Quick note (typed)
2. Image upload / photo file
3. Upload document or PDF
4. Link / article URL

Fold “case,” “quotation,” “observation,” and “idea” into quick note plus an optional type tag. Voice notes and in-app camera can return after the core loop works.

## 16.3 Intent State: “I Am Not Sure Yet”

Every Artifact should carry an explicit intent field:

| Value | Meaning |
|-------|---------|
| `unknown` | Saved without a clear use (“I am not sure yet”) |
| `developing` | User or system sees emerging direction |
| `project-bound` | Linked to one or more Projects |

This powers semantic queries such as “things I saved but never developed,” Daily Reappearance, and Opportunity Detection without forcing tags at capture time.

## 16.4 MVP Intelligence Priority

Promote **Creative Collision** into MVP. Defer Audience Lens, Perspective Shift, and Contrarian Mode to v1.1.

Recommended MVP intelligence order:

1. Capture and brief description
2. Basic + semantic search
3. “What could this become?”
4. Creative Collision (two or three Artifacts)
5. Idea formation
6. Convert Idea → Project

## 16.5 Typed Connections

A Connection is not a vague “related” link. Each Connection should include:

- **Type:** `thematic` | `causal` | `contrast` | `visual` | `evidentiary` | `serendipitous`
- **Origin:** `ai_suggested` | `user_confirmed`
- **Confidence:** numeric or categorical score when AI-suggested
- **Rationale:** one-sentence explanation of why the link exists

Permanent Connections require user approval (see Section 14).

## 16.6 Output Studio: Concept vs Draft

Split Output Studio into two stages:

| Stage | Produces | When available |
|-------|----------|----------------|
| **Concept** | Central idea, audience, format rationale, outline, title options, first next step | From Idea or selected Artifacts (MVP) |
| **Draft** | Near-complete text or structured creative document | Only after a Project exists and source Artifacts are attached |

MVP focuses on Concept-level outputs. Full drafts come later to reduce hallucination risk and honor AI Behavior Rules.

## 16.7 Confidentiality as a Hard Gate

Confidentiality is not merely metadata. Levels:

| Level | Behavior |
|-------|----------|
| `personal` | Normal processing |
| `work` | Normal processing; may exclude from some resurfacing |
| `privileged` | Skip cloud AI or use redacted / local path only |
| `do-not-send-to-model` | Store and search locally; never send content to external models |

The capture flow should make the privileged / do-not-send options easy to set without slowing ordinary captures.

## 16.8 Relationship to Inside Black Boxes

**Decision:** Inside Black Boxes is not a sibling product and not the primary brand of this app. It lives inside Blackletter Lab as a **Project Underway**.

- Blackletter Lab is the product: the private creative intelligence library.
- Inside Black Boxes appears in a **Projects Underway** area (alongside other active creative or professional efforts).
- Episode materials, outlines, show notes, clips, and research for the podcast may be captured as Artifacts and developed through Ideas → Project → Outputs within that project.
- The podcast’s public site, RSS, and publishing pipeline remain separate concerns; Blackletter Lab holds the working library and creative development for that project (and others).

**Navigation implication:** Prefer a **Projects Underway** surface (active projects the user is developing) over treating Inside Black Boxes as top-level product chrome.

## 16.9 Additional Differentiator

State explicitly:

> Blackletter Lab provides **provenance-preserving creative development**: every Output carries lineage back to original Artifacts and the user’s own descriptions.

Competitors often store notes *or* generate content. The differentiator is doing both with an auditable Idea Lineage trail.

## 16.10 MVP Acceptance Criteria (Initial)

Use these as buildable success checks; expand as features land.

| Feature | Acceptance criterion |
|---------|----------------------|
| Quick capture | User can save a note, photo, or link with a one-sentence description in under 30 seconds |
| Intent | Artifacts marked “I am not sure yet” are queryable as undeveloped material |
| Semantic search | Query returns ≤20 results; each shows match reason and confidence; Artifact opens without leaving search context |
| What could this become? | Selecting one Artifact yields ≥3 Concept suggestions, each with title, audience, format, and next step |
| Creative Collision | Selecting two Artifacts yields ≥2 plausible combination Ideas with rationale |
| Connections | AI suggestions are pending until user confirms; confirmed Connections show type and rationale |
| Output Concept | User can generate a Law360, LinkedIn, or short-film Concept from a Project without producing a full draft |
| Confidentiality | Material marked `do-not-send-to-model` never appears in outbound AI request payloads |
| Lineage | Every saved Output lists source Artifacts and accepted AI contributions |
